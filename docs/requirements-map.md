# Соответствие заданию и учебным материалам

Источники — восемь приложений пользователя. Текст семи DOCX прочитан из WordprocessingML; двоичный «Проектный практикум (2).doc» прочитан antiword. Иллюстрации документов не считаются проверенными спецификациями API. Письменный запрос пользователя имеет приоритет над упомянутыми перспективными интеграциями.

| Источник | Смысл требований | Реализация / отличие |
|---|---|---|
| Лаб_раб_ПП_1 (3) | Версии, изменения, объекты и объяснимый отчёт; анализ отдельно от тестирования | `impact`, таблицы `impact_*`; пути и отчёт; состав команды — контекст, не данные продукта |
| Лаб_раб_ПП_2 (2) | BSL Language Server как источник связей, EDT для экспертной проверки, собственный граф | Реальный NetworkX; Protocol для программных связей. BSL, EDT, SonarQube не подключены |
| Лаб_раб_ПП_3 (2) | Импорт, граф, сравнение, направление, циклы, несколько причин, удалённые узлы, сохранение и передача | Проверяемый JSON 1.0; транзакционные импорты; обратный обход; граф целевой версии в UI; пути удалённых объектов отдельно в отчёте. Синхронные ограниченные операции, без очереди фоновых задач |
| ПП №1 | Сопоставление зоны с каталогом, историей и дефектами; три подсистемы | `intelligence`; исполнение — только контракт. MCP, упомянутый в исследовании, заменён требуемым HTTP+JSON |
| ПП №2 | Анализ аналогов и обоснование интеллектуального отбора | Прозрачная взвешенная модель плюс настоящая логистическая регрессия с допуском качества, без заявления превосходства над аналогами |
| ПП №3 | Ф-01–Ф-15: валидация, каталог, подтверждение связей, история, score, ML fallback, бюджет, mandatory, JSON/CSV, внешний результат | API, модели и тесты; изменения существующего ID входного пакета дают явный 409 вместо автоматической редакции; CSV-импорт отложен, JSON реализован |
| ПП №4 | Процесс приём → сопоставление → оценка → оптимизация → эксперт → внешний runner | Передача через API; аудит и роли; конфликты требуют явного экспертного отклонения; импорт внешних результатов без запуска 1С |
| Проектный практикум (2).doc | Python / FastAPI / NetworkX / PostgreSQL; сущности теста, покрытия, прогона, дефекта, приоритета и набора | Соответствующие отдельные таблицы `ti_*`, две ревизии Alembic; практическая интеграция с 1С отложена по запросу |

## Проверка пунктов запроса

| Пункты | Поставка | Проверка / граница |
|---|---|---|
| 1–3 | Монорепозиторий, два самостоятельных API, web, PostgreSQL | Compose, миграции; прямого чтения таблиц impact вторым сервисом нет |
| 4 | Учебные типы объектов, идемпотентный импорт, checksum, diff и граф | `tests/test_impact.py`; контроль схемы и ссылок, базовый/целевой граф, лимиты путей |
| 5.1–5.3 | CRUD с архивированием, состояния покрытия и аудит, история, нормированные веса и факторы | `tests/test_intelligence.py`, `test_optimizer.py`; critical по умолчанию mandatory, снятие/понижение требует эксперта и причины |
| 5.4 | scikit-learn LogisticRegression, временная валидация, параметры/метрики в PostgreSQL, fallback | Исторические признаки только из завершённых предшествующих событий. Критичность и длительность — текущие значения каталога; исторические редакции каталога не восстановлены |
| 5.5–5.6 | Точный перебор до 18 необязательных кандидатов, жадный далее, два знаменателя, JSON/CSV, экспертная правка | Явные конфликты; сохранение первоначального расчёта в `ti_priorities`, итогового выбора и аудита |
| 6 | Версионированный пакет, checksum, API доставки и повтор | `ImpactPackage`, HTTP smoke; анализ сохраняется до попытки отправки |
| 7 | Экспорт execution job и приём immutable report | Контракт и API; нет подключения OData/Vanessa и автоматического passed |
| 8 | Восемь рабочих разделов на русском, SVG-граф с фильтрами/масштабом/путями | API-подключение и браузерный сценарий; редакторы сложных структур — JSON, без визуального конструктора |
| 9 | PostgreSQL, миграции, индексы, FK, уникальность, роли, env, лимит 8 МиБ, аудит | HTTP Basic для локального MVP; нет SSO, распределённых прав или промышленного hardening |
| 10–11 | 16 сценариев, две версии, 12 прогонов, synthetic маркировка, pytest и smoke | Живая 1С отсутствует; синтетические данные изолированы `configuration_id` и признаком происхождения |
| 12 | Воспроизводимый benchmark 10000 узлов и 1000 сценариев | Размер и глубина фиксируются в результате; SLA реальной конфигурации не подтверждён |
| 13–15 | README, Compose, документация и сквозной сценарий | Точные результаты проверок — `docs/validation.md`; ограничения — отдельный документ |
