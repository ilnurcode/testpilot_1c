## Меры против повтора

Предупреждение в шапке приёмки и README (не запускать `down -v` на стенде с данными); CI — в проекте `testpilot-ci`; есть `scripts/backup.sh`/`.ps1` (`pg_dump` в `.runtime/backups/`).
Технический предохранитель: `scripts/compose.sh`/`compose.ps1` защищают скрипты репозитория, которые их вызывают:
`down -v`, `volume rm`, `volume prune` рабочего проекта получают отказ с кодом 3, разрешены только для `-p testpilot-ci`
или `-p testpilot-restore`; `CI=1` запрет не снимает. Прямой `docker compose down -v` обёртка не перехватывает
(проверяется `tests/test_compose_guard.py`).

## Восстановление, если найдётся дамп

Восстановление в уже мигрированную БД **не поддерживается**: схема `public` должна быть пуста.
Порядок (`restore.sh`/`.ps1` — черновик, на реальном дампе не проверялись, только отдельный стек):
1) `docker compose -p testpilot-restore up -d db` — только база, без `migrate`;
2) `bash scripts/restore.sh --dump путь.sql --yes --project testpilot-restore` (нужен `--yes`; `--force` убран,
   при N таблицах в схеме — отказ; `psql -v ON_ERROR_STOP=1` для `.sql`, `pg_restore --clean --if-exists --no-owner` для `.dump`);
3) если в дампе есть `alembic_version` — `docker compose -p testpilot-restore up -d --wait`; иначе сверить таблицы
   и выполнить `alembic stamp head` вручную (`up -d --wait` до этого упадёт: `migrate` создаст существующие таблицы).

Если дампа нет и нужно искать данные в копии диска — [forensic-playbook.md](forensic-playbook.md). Создать демо-данные заново — [recreate-demo.md](recreate-demo.md).
