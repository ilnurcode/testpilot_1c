# Запуск TestPilot 1C на Windows одним двойным щелчком

Эта инструкция для Windows 10/11. Для обычного запуска вам нужен только Docker Desktop: Python, Git, Ubuntu, PowerShell-команды и установка Playwright не требуются. Приложения, база PostgreSQL и браузер тестов работают в Docker-контейнерах. Внутренне Docker Desktop может использовать WSL2, открывать Ubuntu не нужно.

## 1. Установите Docker Desktop

1. Перейдите на официальный сайт: https://docs.docker.com/desktop/setup/install/windows-install/
2. Установите Docker Desktop. Примите условия лицензии и выберите рекомендованный WSL2 backend.
3. Перезагрузите компьютер, если установщик попросит.
4. Запустите Docker Desktop через меню «Пуск» и дождитесь, пока движок будет готов.
5. Убедитесь, что выбран режим **Linux containers**. В меню Docker возле часов пункт **Switch to Windows containers** означает, что Linux-режим уже выбран.

При установке Docker может потребоваться аппаратная виртуализация. Если Docker сообщает о WSL, попробуйте обновить WSL через предложенную самим Docker подсказку. На рабочем компьютере для изменения системных настроек может понадобиться администратор.

## 2. Скачайте проект

1. Откройте страницу проекта: https://github.com/ilnurcode/testpilot_1c
2. Нажмите зелёную кнопку **Code**, затем **Download ZIP**.
3. Дождитесь загрузки архива и выберите **Извлечь всё** в Проводнике.
4. Откройте распакованную папку `testpilot_1c-main`.

Локальные Git и Python для этого варианта не нужны. Не запускайте `.ps1` и не вводите команды в терминал. Не запускайте файл напрямую из окна ZIP: сначала извлеките его целиком. Внутри папки должен быть файл `compose.yaml`.

## 3. Запустите TestPilot

Дважды щёлкните:

```text
Run-TestPilot.bat
```

Если расширения файлов скрыты Проводником, имя может отображаться как **Run-TestPilot**. Windows откроет небольшое чёрное окно запуска. Не закрывайте его до появления сообщения о готовности. Если Windows показывает подтверждение запуска скачанного файла, проверьте, что вы распаковали ZIP репозитория TestPilot, и запускайте этот файл из распакованной папки.

При первом запуске лаунчер откроет Docker Desktop, если тот ещё не запущен, и подождёт запуска движка. Затем Docker скачает базовый образ, Python-библиотеки и Chromium и соберёт контейнеры. Это может занять несколько минут; время зависит от скорости интернета и компьютера. Желательно иметь не менее 5 ГБ свободного места. Во время первой загрузки может появиться окно Docker Desktop с условиями использования — завершите настройку.

Когда увидите:

```text
TestPilot is ready: http://localhost:8000
```

лаунчер сам откроет браузер. Если страница не открылась, нажмите в нём ссылку или откройте вручную:

```text
http://localhost:8000
```

На локальном компьютере используйте логин **expert** и пароль **TestPilotLocal123!**, если вы не задавали свои настройки в файле `.env`.

Лаунчер покажет диагностику, если Docker Desktop не найден, не готов или сборка завершилась ошибкой. Оставьте окно открытым и прочитайте сообщение внизу. Повторный запуск того же файла продолжает сборку или запускает уже созданные контейнеры.

## 4. Что происходит при запуске

Docker Compose поднимает PostgreSQL, одноразовый контейнер миграций, два API и веб-приложение. Chromium находится в контейнере исполнителя. Весь код работает внутри Docker; localhost:8000 — только локально открытый веб-интерфейс.

Веб-приложение доступно только на этом компьютере. Порты базы данных не открываются для других устройств сети. Текущие локальные учётные записи и настройки предназначены для демонстрации на личном компьютере, не для размещения публичного сайта.

В базе сохраняются загруженные файлы, проекты, планы, история, результаты и скриншоты. Они находятся в именованном Docker volume, поэтому сохраняются при остановке и следующем запуске. Удаление проекта через Docker Desktop или сброс данных Docker может стереть их.

## 5. Демонстрация

1. В браузере на стартовом экране нажмите **Обзор → Открыть демонстрацию**.
2. Откройте **Проекты и файлы** и покажите две сохранённые учебные версии.
3. Посмотрите анализ изменений: в подготовленном примере 5 изменений, 10 затронутых объектов и объясняющие пути связей.
4. В отчёте нажмите **Подготовить проверки**.
5. Без API-ключа выберите **Учебные правила — без нейросети**, затем **Сформировать сценарии**.
6. Просмотрите предложенные сценарии и ожидаемые суммы. Введите причину, например «Проверены сценарии и данные для расчёта скидки», затем подтвердите оба сценария.
7. Нажмите **Запустить на учебном стенде**.
8. Покажите фактические значения и скриншоты браузерных шагов.
9. Обновите страницу: отчёт остаётся сохранённым.

В отчёте ожидаются две пройденные проверки и два расхождения. Учебный стенд специально содержит ошибку: при количестве 10 скидка теряется, и вместо ожидаемых 900 получается 1000. Это найденная ошибка синтетического приложения. Это не тестирование настоящей 1С.

Для показа достаточно учебного режима — API-ключ не нужен. Вызов настоящей нейросети требует отдельно заданного API-ключа и согласия на отправку контекста провайдеру. Фактический вызов модели с ключом ещё не проверялся.

## 6. Остановка и повторный запуск

Чтобы штатно остановить TestPilot, дважды щёлкните:

```text
Stop-TestPilot.bat
```

Скрипт остановит контейнеры, сохранив базу данных. Когда снова захотите открыть приложение, дважды щёлкните `Run-TestPilot.bat`. Docker Desktop должен быть установлен; лаунчер запустит его, если он закрыт.

Не нажимайте **Delete volumes**, не выбирайте сброс данных Docker Desktop и не используйте очистку томов, если хотите сохранить файлы и результаты. При штатной остановке остановочный файл выполняет `docker compose down` без удаления тома.

## 7. Обновление приложения

1. Снова скачайте ZIP репозитория кнопкой **Code → Download ZIP**.
2. Извлеките его в новую папку.
3. Перенесите `.env`, если вы создавали собственные настройки или API-ключ, но внимательно сохраните резервную копию.
4. Для переноса базы в новой версии не удаляйте volume старой установки. Если просто открыть ZIP в другой папке, Docker Compose может создать отдельную базу. Поэтому для обычного обновления проще заменить файлы в прежней папке после остановки `Stop-TestPilot.bat`, сохраняя Docker volume и `.env`.
5. Запустите `Run-TestPilot.bat`. Docker перестроит изменившиеся контейнеры и применит миграции.

Для пользователя, который ещё не менял настройки и не хранил пользовательские файлы, наиболее простой вариант — распаковать свежий ZIP в новую папку и запустить его.

## 8. Настройка нейросети — необязательно

Для учебной демонстрации ключ не нужен. Если есть ключ OpenAI-совместимого API, создайте текстовый файл `.env` в той же папке, где лежит `compose.yaml`. В Проводнике может потребоваться включить **Вид → Показать → Расширения имён файлов**, чтобы создать именно `.env`, а не `.env.txt`.

Добавьте в файл, подставив реальные настройки провайдера:

```dotenv
TP_LLM_BASE_URL=https://api.openai.com/v1
TP_LLM_MODEL=gpt-4.1-mini
TP_LLM_API_KEY=ВСТАВЬТЕ_КЛЮЧ_СЮДА
```

Сохраните файл и запустите приложение повторно. Ключ остаётся локальным и не публикуется в GitHub. Не присылайте его в чат и не добавляйте `.env` в архив проекта. API-доступ может быть платным; подписка ChatGPT сама по себе не является API-ключом. В интерфейсе выберите API и согласитесь на передачу контекста провайдеру. Наличие ключа не гарантирует доступ к модели.

## 9. Устранение ошибок

| Сообщение или проблема | Что сделать |
| --- | --- |
| Docker Desktop не найден | Установите Docker Desktop по ссылке выше, перезагрузите Windows при необходимости и повторите двойной щелчок. |
| `dockerDesktopLinuxEngine` или движок недоступен | Откройте Docker Desktop, дождитесь готовности. Убедитесь, что используется Linux containers. |
| Лаунчер долго ожидает запуска Docker | Дайте Docker Desktop закончить первичную настройку. Если появится запрос согласия с лицензией, подтвердите его в окне программы. |
| Сборка прервалась или нет интернета | Проверьте интернет и свободное место, оставьте Docker Desktop работающим и ещё раз запустите `Run-TestPilot.bat`. При ошибке окно показывает статус контейнеров и последние журналы. |
| Порт уже используется | Закройте только известное приложение, которое занимает порт 8000, 8001, 8002 или 5432, и повторите запуск. Не завершайте неизвестные процессы наугад. |
| В браузере `ERR_CONNECTION_REFUSED` | Убедитесь, что лаунчер сообщил о готовности. Оставьте Docker Desktop запущенным и повторите запуск. |
| Пароль не подходит | Для новой настройки без `.env` используйте `expert` / `TestPilotLocal123!`. Если есть `.env`, проверьте значение `TP_EXPERT_PASSWORD` в нём. Не отправляйте содержимое файла другим людям. |
| В интерфейсе нет прежних проектов | Проверьте, что используете исходную папку Compose-проекта. Другая папка Compose может означать другую базу. Не удаляйте старые контейнеры и тома, пока не найдены данные. |
| Docker сообщает о WSL/виртуализации | Выполните диагностические указания Docker Desktop. На рабочем компьютере обратитесь к администратору. Открывать Ubuntu для запуска сервиса всё равно не требуется. |

Чтобы повторно увидеть сообщения об ошибке, вновь запустите `Run-TestPilot.bat` — последние журналы будут показаны при ошибке старта. Перед отправкой журнала убедитесь, что там нет приватных данных и ключей.

## 10. Границы текущей версии

В сервисе можно демонстрировать сохранение файлов, сравнение нормализованных версий, объяснимый анализ влияния, подготовку сценариев, экспертное подтверждение, запуск HTTP/Playwright на отдельном учебном приложении и сохранённый отчёт.

Настоящая информационная база 1С, OData, веб-клиент 1С, выполнение тестов в самой 1С и автоматический разбор бинарных CFE/CF/EPF/ERF/DT пока не подключены. Они требуют отдельной интеграции и проверки на предоставленной тестовой базе. Учебный исполнитель строго ограничен синтетическим стендом.

В облачном Linux прошли 87 тестов с PostgreSQL, проверка Compose и миграций. HTTP/Playwright-демонстрация приложения ранее проверялась на хостовом Linux; полный Docker build с Chromium здесь остановился из-за сетевой недоступности package index. Полный запуск Docker Desktop на физическом Windows в среде разработки не проверялся. Если проблема останется, сообщите текст ошибки из окна запуска. Файлы `.env` и пароли никому не пересылайте.

Для расширенного запуска приложений непосредственно в Windows используйте [отдельную инструкцию PowerShell](windows-powershell.md).
