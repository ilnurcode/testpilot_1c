# Windows: установка и запуск из PowerShell

Приложения и Playwright работают непосредственно в Windows. Команды Ubuntu и uv не нужны. PostgreSQL запускается в Docker Desktop; при стандартной настройке Docker использует WSL2 внутри, но открывать Ubuntu и устанавливать в ней проект не требуется. Если нужен прежний вариант целиком внутри WSL, см. [отдельную инструкцию](windows-wsl.md).

## 1. Установите необходимые программы

Поддерживаемый целевой вариант: Windows 10/11 x64, Python **3.12 x64**, PowerShell 5.1 или 7, Git и Docker Desktop с Compose v2. Совместимость самого Docker Desktop с вашей сборкой Windows уточняйте в его актуальных требованиях.

Установщики:

- Python 3.12: https://www.python.org/downloads/windows/ — установите Python launcher (`py`); если предлагается, включите Add python.exe to PATH.
- Git: https://git-scm.com/download/win
- Docker Desktop: https://docs.docker.com/desktop/setup/install/windows-install/ — включите Linux containers и рекомендуемый WSL2 backend. Перезагрузите Windows, если этого требует установка.

Вместо скачивания вручную можно использовать winget, если он доступен, в PowerShell:

```powershell
winget install --exact --id Python.Python.3.12
winget install --exact --id Git.Git
winget install --exact --id Docker.DockerDesktop
```

Установщики могут запросить права администратора. Для самого проекта обычного PowerShell достаточно. После установки откройте **новый PowerShell**, запустите Docker Desktop и дождитесь готовности движка.

Проверьте:

```powershell
py -3.12 --version
git --version
docker version
docker compose version
```

Docker version должен показывать Client и Server; Compose — v2. Отдельная Ubuntu не требуется. Не устанавливайте одновременно две копии проекта — Linux `.venv` несовместима с Windows `.venv`.

## 2. Скачайте проект

В обычном PowerShell:

```powershell
New-Item -ItemType Directory -Force "$HOME\Projects" | Out-Null
Set-Location "$HOME\Projects"
git clone https://github.com/ilnurcode/testpilot_1c.git
Set-Location testpilot_1c
```

Если проект уже скачан, перейдите в его папку и выполните `git pull --ff-only`. Не клонируйте поверх существующих файлов. Не используйте папку внутри OneDrive для виртуального окружения и работающих процессов.

Для приватного репозитория войдите в GitHub через Git Credential Manager на своём компьютере. Не вставляйте токены в URL и сообщения.

## 3. Установите зависимости

Если политика PowerShell блокирует локальные скрипты, разрешите их **только для текущего окна**:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
```

Это не меняет постоянную политику компьютера. Если действует корпоративная Group Policy, обратитесь к администратору; обходить её не нужно.

Из корня проекта выполните:

```powershell
.\scripts\install.ps1
```

Скрипт проверит Docker и Python, создаст `.venv`, установит Python-зависимости и совместимый Windows Chromium, создаст локальный `.env` со случайными паролями и проверит запуск браузера. Интернет нужен для первой установки. Значения секретов скрипт не печатает. Активация `.venv` вручную не требуется.

Существующий `.env` сохраняется. Если вы перенесли его с Linux, удалите или исправьте **только** строку `TP_CHROMIUM_PATH=/usr/bin/chromium`: без этой переменной Windows использует браузер Playwright автоматически. Не удаляйте весь .env при сохранённой базе — пароль БД должен совпадать с уже установленным.

Не копируйте пустой `.env.example` поверх созданного файла. В Windows chmod не даёт POSIX-изоляции файла: храните проект в личной папке пользователя с подходящими NTFS-правами, не делитесь `.env`.

## 4. Запустите

```powershell
.\scripts\start.ps1
```

Скрипт проверит браузер, поднимет только PostgreSQL в Docker, применит миграции и запустит три приложения в фоне на 127.0.0.1. Ожидайте сообщение `Ready: http://localhost:8000`.

Откройте **http://localhost:8000** в обычном браузере Windows. Логин: **expert**. Пароль находится в локальном `.env`, в строке `TP_EXPERT_PASSWORD`. Открыть файл:

```powershell
notepad .env
```

Не показывайте этот файл при трансляции экрана. Другие роли — analyst и runner со своими паролями. Секреты и .env исключены из Git.

Повторный start перезапускает только процессы из сохранённых записей этого проекта. Перед завершением проверяются PID, время создания, путь Python и командная строка. Занятые чужими приложениями порты дают ошибку. Браузер автоматически не открывается, исходные данные демонстрации автоматически не загружаются.

## 5. Покажите демонстрацию

1. **Обзор → Открыть демонстрацию**.
2. Покажите две сохранённые версии, 5 изменений и 10 затронутых объектов.
3. **Подготовить проверки → Учебные правила — без нейросети → Сформировать сценарии**.
4. Проверьте данные, введите причину подтверждения и подтвердите оба сценария.
5. Нажмите **Запустить на учебном стенде**.
6. Покажите 2 пройденные проверки, 2 расхождения, ожидаемые/фактические суммы и скриншоты.
7. Обновите страницу — отчёт сохранится в БД.

Расхождения намеренные: учебный стенд теряет скидку при количестве от 10. Это фактические HTTP/Playwright-проверки синтетического приложения; подключение к настоящей 1С/OData пока не реализовано. API-ключ для такого показа не требуется. [Подробный сценарий показа](presentation.md).

## Остановка и повторный запуск

Остановить приложения, оставив PostgreSQL запущенным:

```powershell
.\scripts\stop.ps1
```

Остановить приложения и PostgreSQL:

```powershell
.\scripts\stop.ps1 -Database
```

`.env`, загруженные файлы, отчёты и volume `testpilot_pgdata` сохраняются. Не используйте `docker compose down -v` или factory reset Docker для обычной остановки — это может удалить данные. Скрипт останавливает также дочерние процессы Windows Python launcher, но не закрывает остальные приложения Python.

После перезагрузки запустите Docker Desktop и откройте PowerShell:

```powershell
Set-Location "$HOME\Projects\testpilot_1c"
Set-ExecutionPolicy -Scope Process -ExecutionPolicy RemoteSigned
.\scripts\start.ps1
```

## Обновление

Если нет локальных правок исходников:

```powershell
.\scripts\stop.ps1
git pull --ff-only
.\scripts\install.ps1
.\scripts\start.ps1
```

Install обновит зависимости и Chromium, start применит миграции. Пользовательские данные не удаляются. При локальных правках сначала сохраните их, не используйте reset --hard для обхода ошибки Git.

## Необязательная проверка из PowerShell

После запуска:

```powershell
. .\scripts\windows-common.ps1
Import-LocalEnv
& .\.venv\Scripts\python.exe scripts\smoke.py --health-only
& .\.venv\Scripts\python.exe scripts\presentation-smoke.py
```

Presentation smoke создаёт отдельный учебный анализ, выполняет HTTP/Playwright и проверяет историю и PNG. Ожидается passed=2, failed=2, error=0, screenshots=2. Пароли не печатаются.

## Необязательная нейросеть

В локальном `.env` можно добавить параметры OpenAI-совместимого провайдера:

```dotenv
TP_LLM_BASE_URL=https://api.openai.com/v1
TP_LLM_MODEL=gpt-4.1-mini
TP_LLM_API_KEY=ВАШ_КЛЮЧ
```

Реальный ключ впишите только локально и перезапустите start.ps1. Не отправляйте его в чат, GitHub или файлы проекта. API-доступ может быть платным; подписка ChatGPT сама по себе не даёт API-ключ. Перед передачей контекста провайдеру интерфейс требует согласие. Фактический вызов с реальным ключом в облачной среде не проверен.

## Устранение ошибок

| Ошибка | Что сделать |
|---|---|
| `py` или Python 3.12 не найден | Установите Python 3.12 x64 с launcher и откройте новый PowerShell. |
| Скрипт заблокирован политикой | Используйте RemoteSigned только в Process scope, как выше. Для ZIP с меткой интернета проверьте происхождение файлов; предпочтительно клонировать через Git. |
| docker не найден / Server недоступен | Запустите Docker Desktop, выберите Linux containers, проверьте `docker version`. |
| Несовместимая .venv | Если папка перенесена из Linux, переименуйте только `.venv` и повторите install.ps1. Сохраните `.env`. |
| Chromium не найден | Повторите install.ps1; удалите неверный TP_CHROMIUM_PATH или укажите настоящий Windows-путь без внешних кавычек. |
| Порт занят | Нужны 5432, 8000, 8001, 8002. Определите конфликтующее приложение. Не завершайте чужие процессы наугад. |
| PID record does not match | Скрипт отказался трогать процесс с неподтверждённой принадлежностью. Проверьте соответствующий `.runtime/windows-*.json` и командную строку процесса; это может случиться после перемещения папки. |
| 401 в браузере | Используйте expert и пароль именно из локального .env этой установки. |
| Ошибка пароля БД после замены .env | Восстановите исходный пароль из своей защищённой копии. Новый случайный пароль не изменяет существующую БД. |
| Не открывается интерфейс | Проверьте `Invoke-RestMethod http://127.0.0.1:8000/health` и логи ниже. Не публикуйте сервис в интернет для обхода локальной ошибки. |

Логи доступны в `.runtime/windows-impact.log`, `.runtime/windows-impact.error.log` и аналогичных файлах intelligence/web:

```powershell
Get-Content .runtime\windows-web.error.log -Tail 50
docker compose logs --tail=50 db
```

Перед пересылкой логов проверьте отсутствие секретов. Приложения слушают только localhost; это локальная демонстрация с общими ролями, не готовая публичная многопользовательская установка.

## Граница проверки

В облачном Linux прошли 84 pytest с PostgreSQL. На PowerShell 7.4.19 для Linux прошли синтаксический разбор всех четырёх скриптов и `tests/windows-smoke.ps1`: буквальная загрузка .env, ошибки внешних команд, пути с пробелами, отказ при чужом процессе/повторно использованном PID, аргументы остановки дерева процессов и повторная остановка. Win32-процессы в этой проверке подменяются контрольными объектами; чужие реальные процессы не завершаются.

Это не заменяет полный запуск Windows: Docker Desktop, настоящий Win32_Process, NTFS и Windows Chromium здесь недоступны. Windows PowerShell 5.1 также отдельно не запускался. Успешная установка на реальном Windows пока не заявляется.
