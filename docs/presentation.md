# Презентационный запуск TestPilot 1C

## Что демонстрируем

Реальный локальный цикл на явно синтетическом проекте: сохранение двух файлов → вычисление изменений и зоны влияния → предложение сценариев и данных → экспертное подтверждение → фактические HTTP-запросы и Playwright → сохранённый отчёт с успешными и неуспешными проверками, ожидаемыми/фактическими значениями и скриншотами.

Стенд продаж — отдельное учебное web-приложение. В нём намеренно оставлена ошибка: ветка оптового заказа (quantity ≥ 10) теряет скидку. При количестве 2, цене 100 и скидке 10 итог 180 совпадает с ожидаемым. При количестве 10 итог ошибочно 1000 вместо 900. HTTP и браузер действительно обращаются к приложению; статусы не назначаются заранее.

## Запуск в подготовленной cloud-среде

Для запуска непосредственно из Windows используйте [PowerShell-инструкцию](windows.md). Команды ниже предназначены для Linux/cloud.

```bash
cd /workspace/testpilot_1c
./scripts/start-presentation.sh
```

Скрипт устанавливает зависимости из lock, проверяет запуск Chromium/Playwright, поднимает PostgreSQL в Compose, выполняет миграции до 0004 и запускает три приложения на хосте. Останавливает только контейнеры данного Compose-проекта и проверенные PID его uvicorn-процессов. `.env` и PostgreSQL volume сохраняются. Автоматической загрузки демонстрации нет.

Требуются Python 3.12, uv, Docker Compose и системный Chromium. Здесь браузер доступен как `/usr/bin/chromium`; для другого расположения задайте TP_CHROMIUM_PATH. На иной ОС сначала установите Chromium из доверенного источника и его системные зависимости. Скрипт проверяет реальный запуск браузера, а не только наличие файла.

Обычные Python Docker-образы не включают Chromium: интерфейс и API в них работают, но браузерный исполнитель потребует дополнительной настройки. Проверенная презентационная конфигурация — приложения и Chromium на хосте, PostgreSQL в Compose. Не путайте её с прежней проверкой Docker-базы MVP.

В браузере используйте адрес web-процесса на порту 8000. Вход: expert, пароль из локального .env. Сам пароль и API-ключи не публикуются в инструкции.

## Сценарий показа на 5–7 минут

1. **Обзор → Открыть демонстрацию.** Создаётся отдельный проект presentation-sales. Две учебные JSON-версии реально загружаются через API, сохраняются и сравниваются. Повторный запуск не дублирует исходные файлы, но создаёт новый анализ.
2. Покажите историю файлов, 5 изменений и 10 затронутых объектов. У каждой записи есть объясняющие пути; ограничения исходных данных перечислены отдельно.
3. В отчёте нажмите **Подготовить проверки**. Без API-ключа выберите **Учебные правила — без нейросети**, затем **Сформировать сценарии**. Это явно маркированный детерминированный источник, а не скрытая имитация LLM.
4. Покажите два сценария: HTTP-проверка данных и Playwright. У каждого — обоснование, затронутые объекты, шаги и два набора входных/ожидаемых значений. Плановое покрытие не называется доказанной полнотой.
5. Введите причину подтверждения, нажмите **Подтвердить выбранные сценарии**, затем **Запустить на учебном стенде**. Создаются и удаляются записи в отдельной demo_orders; произвольный код нейросети не выполняется.
6. Покажите результат: **2 passed, 2 failed, 0 error**. У двух больших заказов расхождение 900/1000. Откройте настоящие браузерные скриншоты. Ошибки инфраструктуры, ручные сценарии и падения бизнес-проверок различаются.
7. Обновите страницу: план, решение эксперта, результаты и скриншоты сохраняются в PostgreSQL.

Нельзя говорить «протестировали 1С» или «нейросеть уже вызвана», когда использовался учебный режим. Корректная формулировка: «продемонстрирован весь доступный процесс на контролируемом стенде; готов адаптер внешней нейросети, живая 1С — следующий интеграционный пилот».

## Подключение нейросети

Сервер intelligence читает:

- TP_LLM_BASE_URL — HTTPS OpenAI-совместимый адрес, по умолчанию https://api.openai.com/v1;
- TP_LLM_MODEL — модель, по умолчанию gpt-4.1-mini;
- TP_LLM_API_KEY — ключ API, только серверная защищённая переменная.

Не передавайте ключ в чат, клиентский JavaScript, executor_parameters или JSON проекта. Подписка ChatGPT сама по себе не является API-ключом. Для стороннего провайдера требуется поддержка Chat Completions и JSON response_format; модель и доступ проверяются фактическим запросом.

После задания переменных перезапустите intelligence (либо весь start-presentation.sh). В разделе «Нейросеть и проверки» отображаются только наличие ключа, хост и модель; значение ключа не возвращается. Наличие ключа не выдаётся за успешную проверку подключения. В генерации выберите API и явно подтвердите передачу контекста внешнему провайдеру.

В запрос входят ограниченные сведения об изменениях, графе, каталоге и разрешённых фрагментах атрибутов модели. Ответ проверяется Pydantic-схемой; неизвестные тесты/объекты отклоняются. Обязательные тесты, пропущенные моделью, добавляются сервером с предупреждением. До подтверждения каталог не изменяется. Подтверждённые предложения сохраняются как новые тесты с указанным экспертом покрытием. Учебный запуск также записывает реальные результаты в историю и найденные расхождения в дефекты. При ошибке API нет скрытого переключения на учебные сценарии.

Промпт содержит недоверенные исходники как данные; модель не получает полномочий выполнять команды. Никакие сгенерированные Python/JavaScript программы не запускаются: исполнитель понимает только ограниченные типизированные данные сценария.

## Границы текущей поставки

- Реальная 1С, её OData, веб-клиент и бинарные форматы CFE/CF/EPF/ERF не подключены. Учебные HTTP endpoints не являются проверенной OData-публикацией 1С.
- Учебный исполнитель разрешён только для synthetic=true и configuration_id=presentation-sales; запрос запуска реального проекта отклоняется.
- Предложения для неизвестных бизнес-сценариев должны быть manual; универсальной генерации селекторов произвольной 1С не заявляем.
- Выбранные существующие тесты сохраняются и показываются, но для их запуска нужен будущий внешний runner. Учебный запуск выполняет только предложенные сценарии ограниченного стенда.
- Локальная ML-модель остаётся архивным кодом предыдущего прототипа и не участвует в этом пользовательском процессе.
- Доступ по общим ролям, без индивидуального multi-tenant разграничения и промышленной системы очередей.

## Проверки

```bash
set -a
. ./.env
set +a
.venv/bin/pytest -q
.venv/bin/python scripts/presentation-smoke.py
.venv/bin/python scripts/presentation-browser-smoke.py
```

HTTP smoke проверяет фактические результаты, очистку тестовых записей, PNG-артефакты и чтение сохранённого отчёта. Browser smoke проходит весь пользовательский путь и мобильную ширину. API внешней нейросети тестируется контрольными ответами MockTransport; без реального ключа успешный вызов провайдера не заявляется.
