# Фактическая проверка MVP

Проверено 15 октября 2026 в текущей облачной машине, Linux x86_64, CPython 3.12.14, Docker 28.4, PostgreSQL 17 в контейнере. Это проверка текущего экземпляра. Публикация и восстановление в новой cloud-задаче отдельно не проверялись.

## Автоматические проверки

- `.venv/bin/pytest -q`: **44 passed, 0 failed, 0 skipped**. Проверки БД выполнялись с настоящим PostgreSQL в отдельных случайных схемах.
- `docker compose exec -T intelligence pytest -q`: **44 passed, 0 failed, 0 skipped**; тот же набор внутри образа.
- Одна внешняя deprecation warning: установленный Starlette предупреждает о будущем переходе TestClient с httpx на httpx2. На выполнение текущих тестов не влияет.
- `alembic upgrade head`: выполнены отдельные миграции impact/audit и intelligence. `alembic check`: новых незаписанных изменений схемы нет.
- `node --check testpilot/web/static/app.js`: без синтаксических ошибок.
- `scripts/install-cloud.sh`: выполнен целиком; повторная установка сохраняет .env, использует lock, готовит wheels и поднимает Compose с health.
- `scripts/start-local.sh`: выполнен дважды, второй вызов не создал дубликаты; локальный HTTP smoke пройден.

Проверяются: валидация/ссылки/дубликаты/идемпотентность/конфликты импорта; checksum сырых байтов; канонизация; diff связей и характеристик; направление A calls B → изменение B затрагивает A; цепочка/ветвления/циклы/глубина/несколько причин/удаление/неизвестная связь; пакет между сервисами; скоринг/статистика/нормирование; обязательные/бюджет/уникальное покрытие/невыполнимые условия; точный и жадный методы; ML-fallback и допущенная модель на специально разделимом синтетическом unit-наборе; CRUD/права/аудит; история/экспорт/подтверждение/runner-контракт; защита от ложного успеха при ошибке завершения транзакции; запрет NaN/Infinity во вложенных метаданных.

## Браузер и отказоустойчивость

Chromium + Playwright: все восемь разделов, загрузка демо, сравнение, граф и кликабельные пути, HTTP-доставка, каталог, обучение/fallback, расчёт и экспертное подтверждение плана, экспорт задания и сохранённый отчёт. Ошибок JavaScript нет. Добавлена проверка, что результаты предыдущего раздела не остаются на странице плана; переходы и поля блокируются на время операции. Скриншот: `.runtime/web-plan.png` (локальный игнорируемый артефакт).

При остановленном intelligence доставка вернула 503, сохранённый анализ остался доступным. После запуска сервиса отправка вернула 200, повторная отправка — idempotent=true.

PostgreSQL перезапущен, локальные uvicorn остановлены и приложения снова запущены через Compose. Сравнены все существовавшие до перезапуска ID двух версий, восьми анализов и четырёх планов, а также checksum полного отчёта: совпадение. Последующие проверки добавили новые демо-анализы и планы, не изменяя эти снимки.

В процессе разработки исправлены порядок вставки узлов/рёбер под составными FK, завершение транзакции до HTTP-ответа, гонка переходов UI и проверка нечисловых значений. Промежуточные неуспешные проверки не считаются успешными результатами; финальные результаты приведены здесь отдельно.

## Производительность и границы

Точные измерения и параметры — `benchmark-result.json`, повтор: `python scripts/benchmark.py`.

- 10000 вершин / 9999 рёбер, линейная цепочка, один источник, глубина 100: около 0.23 с; 101 затронутый узел.
- Те же размеры, звезда, вся зона 10000 узлов: около 0.34 с.
- 1000 тестов / 500 объектов, жадный метод: около 0.26 с, 100% доступного покрытия на этом наборе.

Не подтверждены: реальная 1С, XML/EDT, BSL LS, OData, Vanessa, производственная точность графа/ML, нагрузочный SLA множества источников, восстановление cloud-снимка в новой задаче. Обычная сетевая Docker-сборка здесь не прошла из-за DNS; **прошла offline-сборка** с предварительным HTTPS-скачиванием пакетов. TLS и проверки артефактов не отключались.
