# Алгоритмы и ограничения

## Сравнение и влияние

Идентичность — object_id. Сравниваются тип, полное имя, родитель, канонизированные характеристики и исходящие связи (включая источник/достоверность). Порядок JSON-ключей и порядок записей объектов/связей не изменяет результат. Изменение только связей помечает их источник изменённым. В отчёте свойства указываются на верхнем уровне (`attributes`, `edges` и т. д.), без рекурсивного diff каждой вложенной строки.

| Тип ребра | Оригинальная семантика | Обход влияния |
|---|---|---|
| calls | A вызывает B | B → A |
| uses | A использует B | B → A |
| belongs_to | ребёнок A принадлежит родителю B | B → A |
| subscribes_to | подписчик A зависит от события/источника B | B → A |
| dynamic / external / unknown | зависимость не доказана | не обходится; предупреждение |

NetworkX MultiDiGraph сохраняет оригинальные связи, происхождение, confidence и версию. Для обычных/добавленных/изменённых источников используется целевой снимок; для удалённых — базовый. BFS запускается детерминированно по каждому источнику. По каждой паре источник/объект сохраняется до трёх кратчайших путей (включая альтернативные типы рёбер), до 20000 путей в отчёте. Цикл не размножает путь: уже входящий в него узел не посещается повторно. Несколько источников не теряются при объединении зоны.

Ограничение max_depth: 0–100, по умолчанию 10. Глубокие цепочки за пределом не входят в зону. Лимит числа путей сопровождается предупреждением о неполноте; полный перебор всех путей намеренно не выполняется. `confirmed=false`, если хотя бы одно ребро имеет confidence<1. Неполнота реальной выгрузки остаётся неизвестной даже при confidence=1. Режим `dependencies` — прямой исследовательский обход, а не направление распространения влияния. Параметры анализа сохранены отдельно от экспортного пакета.

## Скоринг 1.0

Только активные совместимые тесты того же configuration_id и происхождения данных. Подтверждённые связи — единственный источник покрытия; unconfirmed/rejected выводятся отдельно.

`score = Σ weight[f] × factor[f]`, веса неотрицательны и нормируются до суммы 1.

| Фактор | Формула | Вес по умолчанию |
|---|---|---|
| coverage | число уникальных затронутых покрываемых объектов / все затронутые | .35 |
| risk | доля failed среди passed/failed, при отсутствии .1; или допущенный ML-прогноз | .20 |
| defects | min(1, сумма серьёзностей связанных дефектов / max(число passed/failed,1)) | .15 |
| criticality | low=.25, medium=.5, high=.75, critical=1 | .20 |
| cost | 1 / (1 + ожидаемая длительность / 300) | .10 |

Длительность — медиана нескipped исторических длительностей либо каталог; нулевая медиана заменяется заявленной длительностью. Error не считается продуктовым failed; skipped исключается из длительности. При <5 passed/failed статистика помечается недостаточной. Частота дефектов и их сумма тяжести представлены отдельно. В расчёте используются сохранённые данные на момент запроса (будущие даты истории отклоняются). Веса централизованы в PostgreSQL; снимок всех факторов, весов и версии алгоритма хранится с планом.

## Оптимизация

Сначала включаются все доступные mandatory. Невозможность запуска mandatory (отключён/несовместим) фиксируется конфликтом, не игнорируется. Превышение обязательными бюджетов сохраняет обязательный набор и величину превышения. Для остальных:

- ≤18 необязательных кандидатов с покрытием: полный перебор допустимых подмножеств, максимум уникального покрытия, затем суммы score, затем минимум длительности, затем лексикографический ID;
- >18: воспроизводимый жадный выбор по новому покрытию / длительности, далее score / длительности, далее ID. Только положительный прирост покрытия. Гарантия оптимальности отсутствует; конфликт здесь может означать недостаточность эвристики, а не математическую невозможность всех наборов.

Покрытие — множество, повтор объекта не повышает процент. `coverage_available`: знаменатель — все объекты зоны, для которых есть хотя бы один подтверждённый активный совместимый тест. `coverage_all`: знаменатель — вся зона. Пустые знаменатели дают 0, диагностируются отдельно. Порог применяется к available; непокрываемые объекты никогда не скрываются. Статус feasible относится к указанному порогу и бюджету, не к доказанной полноте графа.

Эксперт может изменить доступный состав, но при нарушении бюджета/mandatory/порога обязан явно разрешить отклонение с причиной. Подтверждение не превращает конфликт в успех. Подтверждённый план неизменяем, новый расчёт создаёт новый ID. Начальные приоритеты остаются в `ti_priorities`, экспертное решение — в плане и аудите. Перед экспортом задания ещё раз проверяются активность и совместимость выбранных тестов.

## ML

Настоящая sklearn LogisticRegression (random_state=42, class_weight=balanced). Признаки: предшествующее число прогонов (min(n,100)/100), предшествующая доля failed (по умолчанию .1), критичность и заявленная длительность min(duration,3600)/3600. При обучении для каждого события история включает только результаты того же теста, завершённые строго до его начала; одновременные события не используют результаты друг друга.

Минимум 100 passed/failed, оба класса в train и validation, train≥50. Разделение 80/20 по времени, одинаковые timestamps не пересекают границу. Валидация последовательная: в признаках следующего holdout-события может использоваться уже завершившееся предыдущее событие, а коэффициенты не переобучаются на holdout. Допуск: ROC-AUC≥.65 и balanced accuracy≥.55. Иначе fallback с причиной. Модель хранится как JSON коэффициентов, intercept, метрик, признаков и границ времени — без загрузки pickle. Прогноз заменяет только фактор risk; остальная формула неизменна.

Исторические редакции критичности и длительности каталога не восстанавливаются: модель использует текущие статические значения. Временная утечка результатов предотвращена, но изменения каталога нужно учитывать перед реальным пилотом. Модель имеет ID и статус допуска, однако автоматического мониторинга drift и повторного обучения нет. Синтетические метрики не подтверждают качество на реальных проектах.
